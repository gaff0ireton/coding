フルードグリッド

フルードグリッド（Fluid Grid）とは、ページ幅を格子状の単位に分け、 ブラウザーの表示幅に応じて、各領域の幅や使用する列数を変化させるレイアウト手法です。 「fluid」は液体のように形を変えるという意味で、固定されたpxだけでなく、 %などの相対値で横幅を考えます。

CSS Gridとの違い： ここでいう「グリッド」はレイアウト設計上の格子です。 CSSのdisplay: gridを必ず使う、という意味ではありません。 教科書の中心は「幅や列数が画面に合わせて変化するか」です。

画面幅に応じて「4列 ⇄ 12列」を切り替える例

Webページの幅を12列へ均等に分ける設計はよく使われます。 ただし、12列は代表例であり必須ではありません。 8列や16列など、設計に合う列数を選べます。 この模型は640px未満で4列、640px以上で12列へ切り替わるため、 ブラウザーの幅を変えながら列数と配置の変化を観察してください。

現在の模型：スマートフォン用・4列 タブレット／PC用・12列

1234
メイン：4列すべて
4 ÷ 4 = 100%
サイド：4列すべて
次の行へ移動

狭い画面では4列へ減らし、メインとサイドをそれぞれ横幅100%で縦に並べます。

123456 789101112

8 ÷ 12 = 66.67%

640px以上では12列を使い、メイン8列とサイド4列を横に並べます。

補足｜CSSフレームワークとのつながり

BootstrapやTailwind CSSでも使われる考え方

このように「画面を列へ分け、画面幅に応じて列の使い方や並び方を変える」考え方は、 CSSフレームワークでも利用されています。ただし、2つのフレームワークでは仕組みが少し異なります。

Bootstrap

Bootstrapの標準グリッドは1行を12列として扱い、列幅には割合が使われます。 ブレークポイントごとのクラスを組み合わせることで、スマートフォンでは縦並び、 広い画面では8列＋4列の横並び、といった変更ができます。 

<div class="row">
  <main class="col-12 col-md-8">メイン</main>
  <aside class="col-12 col-md-4">サイド</aside>
</div>

Bootstrapでは各ブレークポイントでも基本の12列は維持されます。 このページの「狭いときは4列へ減らす模型」と内部指定まで完全に同じ、という意味ではありません。

Tailwind CSS

Tailwind CSSには、列数を作るgrid-cols-*と、要素が使う列数を決める col-span-*があります。レスポンシブ用の接頭辞を付けると、 このページの4列から12列へ変わる模型を直接表現できます。 

<div class="grid grid-cols-4 md:grid-cols-12">
  <main class="col-span-4 md:col-span-8">メイン</main>
  <aside class="col-span-4 md:col-span-4">サイド</aside>
</div>

Tailwind CSSは12列を固定の標準にしているわけではありません。 grid-cols-2やgrid-cols-6など、必要な列数を制作者が選びます。

確認資料： Bootstrap公式 Grid system・ Tailwind CSS公式 grid-template-columns

この補足は実務とのつながりを理解するための情報です。資格試験では、まずフルードグリッド自体の意味を優先して覚えましょう。

割合の求め方：使用する列数 ÷ 全列数 × 100。親要素が900pxなら約600pxと300px、親要素が600pxなら約400pxと200pxへ一緒に縮みます。

フルードグリッドで変えられるもの

  1. 領域の幅：%などで親幅に合わせて伸縮させる。
  2. 使用する列数：広い画面では12列、狭い画面では4列のように設計を変えられる。
  3. 配置：PCでは横並び、スマートフォンでは縦並びへ変更できる。
  4. 境界：メディアクエリのブレークポイントで、列数や配置を切り替える。
main 75%
side 25%
/* 広い画面：75%と25%の2列 */
.main { width: 75%; }
.side { width: 25%; }

/* 狭い画面：それぞれ100%にして縦へ並べる */
@media screen and (max-width: 639px) {
  .main,
  .side { width: 100%; }
}

高解像度画面とsrcset

srcset属性は、1つのimg要素へ複数の画像候補を登録し、 画面のピクセル密度やviewport幅などをもとに、ブラウザーへ適切な候補を選ばせる属性です。 画像をCSSで小さく見せるだけでなく、端末に合うファイルを届けられるため、 高解像度画面のぼやけと、モバイル回線での過剰な通信量の両方を調整できます。

CSSピクセルはレイアウト上の論理的な単位、デバイスピクセルは画面の物理的な点です。 DPR（デバイスピクセル比）が2なら、1 CSS pxを縦横2倍、合計4個の物理ピクセルで描けます。 公式出題範囲のdensityは、このような画面密度を表す考え方です。

1 CSS px
DPR 2

srcsetの書式を1つずつ読む

<img src="photo-480.jpg"
     srcset="photo-480.jpg 1x,
             photo-960.jpg 2x"
     alt="森の動物">

候補1photo-480.jpg 1x通常密度向け

区切り,候補同士をカンマで区切る

候補2photo-960.jpg 2x2倍密度向け

1xと2xをx記述子（ピクセル密度記述子）と呼びます。 URLだけで記述子を省略した候補は1xとして扱われます。 ブラウザーは候補をすべて表示したり、必ずすべて読み込んだりするのではなく、通常は状況に合う1つを選びます。

教科書 4-24

w記述子とsizesを実際に使う

w記述子（幅記述子）は、候補画像ファイルの固有の横幅を表します。 480wは「このファイルの元画像は横480px」という意味で、 画面上で必ず480px表示する指定ではありません。実際の画像幅と違う数値を書いてはいけません。

sizes属性は、画像がレイアウト上でどれくらいの幅になる予定かをブラウザーへ伝えます。 CSSの代わりに表示幅を設定する属性ではなく、候補選択のための情報です。 w記述子を使う場合は、ブラウザーが必要な画像サイズを計算できるよう、sizesと組み合わせます。

srcsetには2つの指定方法がある

方法1｜x記述子

画面密度に合わせる
<img src="animal-1x.jpg"
  srcset="animal-1x.jpg 1x,
          animal-2x.jpg 2x,
          animal-3x.jpg 3x"
  alt="森の動物">
  • 1x：通常密度向け。省略時も1x相当。
  • 2x：縦横2倍の画素数を持つ候補。
  • 3x：縦横3倍の画素数を持つ候補。

画像をCSS上で横320px表示するなら、1xは横320px、2xは横640px、3xは横960pxの画像を用意する考え方です。

方法2｜w記述子

画像ファイル本来の幅を伝える
<img src="animal-480.jpg"
  srcset="animal-480.jpg 480w,
          animal-960.jpg 960w,
          animal-1440.jpg 1440w"
  sizes="(min-width: 768px) 50vw, 92vw"
  alt="森の動物">

ブラウザーが表示予定幅と画面密度を計算し、必要量に近い候補を選びます。

混在させない： 同じsrcset内で2xと960wを一緒に使いません。 x記述子方式かw記述子方式のどちらか一方を選びます。

1.sizesで表示予定幅を調べる

2.画面密度を考える

3.必要幅に近いw候補を選ぶ

例：表示予定幅が480 CSS pxでDPR 2なら、約960px分の画像が必要になるため、960w候補が選ばれやすくなります。最終判断はブラウザーに任されます。

<img src="red-panda-960.jpg"
  srcset="red-panda-480.jpg 480w,
          red-panda-960.jpg 960w,
          red-panda-1440.jpg 1440w"
  sizes="(min-width: 768px) 50vw, 92vw"
  alt="霧の森のレッサーパンダ">
  • 480wなどは画像ファイル本来の横幅で、CSSの表示幅ではありません。
  • sizesは画像が画面内でどれくらいの幅になる予定かを伝えます。
  • 同じsrcset内でx記述子とw記述子を混在させません。
  • 候補を全部表示するのではなく、ブラウザーが通常1つを選びます。
★

教科書 4-18・4-19

scriptのsrc・defer・async

外部JavaScriptファイルの場所はsrc属性で指定します。 初学者が最初に区別したいのは、取得（ネットワークからファイルを読む）と 実行（JavaScriptの命令を動かす）は別の処理だという点です。

ブラウザーはHTMLを上から読み、要素をDOMという木構造へ組み立てます。この作業をここでは HTMLの解析（パース）と呼びます。通常の外部scriptに出会うと、 ブラウザーは解析をいったん止め、ファイルを取得・実行してから続きを読みます。 大きなファイルや遅い回線では、その停止時間がページ表示を遅らせる原因になります。

通常HTML解析取得・実行HTML解析
deferHTML解析 ＋ 並行取得解析後、記述順に実行
asyncHTML解析 ＋ 並行取得準備でき次第実行

通常読書を止め、別室から資料を取って読み終えてから本文へ戻る。

defer誰かに資料を取りに行ってもらい、本文を最後まで読んでから順番に確認する。

async誰かに資料を取りに行ってもらい、届いた瞬間に本文を止めて確認する。

<script src="ui.js" defer></script>
<script src="analytics.js" async></script>
  • 通常：解析を止め、取得・実行してから解析を再開。
  • defer：並行取得し、原則として解析後に文書順で実行。
  • async：並行取得し、準備できたものから実行。複数ファイルの順序は保証しない。
通常・defer・asyncの比較
指定取得中のHTML解析実行タイミング複数ファイルの順序判断のポイント
指定なし停止する取得後すぐ文書順解析を止める
defer続けるHTML解析完了後、DOMContentLoadedより前原則として文書順DOMを使う複数スクリプトに向く
async取得中は続ける。実行時は止まる取得でき次第保証されない他に依存しない処理に向く
試験での読み方： 「非同期で取得」はdeferとasyncの共通点です。 違いは、deferが解析後に文書順で実行され、asyncは取得できた順にすぐ実行される点です。

教科書 4-22

電話番号の自動認識とtelリンク

<meta name="format-detection"
      content="telephone=no, email=no, address=no">
<a href="tel:+81312345678">03-1234-5678</a>

format-detectionは、一部のモバイルブラウザーが文字列を電話番号・メールアドレス・住所として 自動認識し、リンクのように扱う機能を制御するmeta設定です。 教科書では3種類をまとめて無効化するコードが掲載されています。

値抑える自動認識明示的にリンクする例
telephone=no電話番号<a href="tel:+81312345678">
email=noメールアドレス<a href="mailto:study@example.com">
address=no住所必要なリンクを制作者が明示する

スペル注意：adressではなく、dが2つのaddressです。

これはHTML Standard全体の汎用設定ではなく、対応ブラウザー向けの拡張です。 Appleの公式資料が明示している中心はtelephone=noで、email・addressの扱いは環境差があります。 資格試験では、まず教科書掲載コードの名前と意味を正確に判別してください。

INTERACTIVE MODEL

telephone=noを付け外しして比較

<meta name="format-detection" content="telephone=no, email=no, address=no">

telephone=no が有効

電話番号らしい文字列でも、自動電話リンクへ変換しない設定です。

03-1234-5678

telephone=no がない

対応ブラウザーが電話番号として自動認識すると、次のようにタップ可能な表示になります。

03-1234-5678

このボタンは実際にhead内のmeta要素を書き換え、同時に自動認識後の見た目を模型として再現します。 実際のブラウザーによる自動認識は通常ページ読み込み時に行われるため、読み込み後にmetaを書き換えただけで 既存テキストが自動的にリンクへ再変換されるとは限りません。

電話で問い合わせ：03-1234-5678（学習用の例）

メールで問い合わせ：study@example.com（学習用の例）
